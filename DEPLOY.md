# Deploying to Vercel

This is a TanStack Start (SSR) app. The production build uses Nitro's
`vercel` preset, which emits Vercel's Build Output API bundle
(`.vercel/output/`). Vercel serves that directly — static assets from a CDN
and server-rendered routes from a Node function.

## One-time setup

1. Push this repo to GitHub (already done on the working branch).
2. In Vercel: **Add New → Project → Import** this GitHub repo.
3. Vercel reads `vercel.json`, so the settings below are already applied —
   just confirm them on the import screen:
   - **Framework Preset:** Other (no framework)
   - **Build Command:** `vite build`
   - **Install Command:** `bun install` (Vercel also auto-detects this from `bun.lock`)
   - **Output Directory:** leave blank — the Build Output API (`.vercel/output`)
     is detected automatically.
4. There are **no required environment variables**. The quiz webhook URL is
   in the code; nothing secret needs to be set.
5. Click **Deploy**.

## Custom domain

The site is configured for `https://upliftmedicalms.com` (canonicals, og:url,
structured data, sitemap, robots.txt).

1. Vercel → Project → **Settings → Domains** → add `upliftmedicalms.com`
   (and `www`), then point DNS at Vercel as instructed there.
2. If the domain ever changes, update `SITE.url` in
   `src/components/site/site-data.ts` plus `public/sitemap.xml` and
   `public/robots.txt`, then commit and push.
3. After launch, submit `https://upliftmedicalms.com/sitemap.xml` in Google
   Search Console.

## Local commands

- `bun install` — install dependencies
- `bun run dev` — dev server on http://localhost:8080
- `bun run build` — production build (writes `.vercel/output/`)
- `bun run lint` — ESLint

## Notes

- Node runtime is pinned to `22.x` (`engines` in `package.json`), matching the
  runtime Nitro targets for the server function.
- `.vercel/` is gitignored — it is generated by the build, not committed.
